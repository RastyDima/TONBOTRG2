# Аватары приложения

Android и Telegram WebApp получают аватар через `GET /app/api/profile/avatar`.
Запрос требует действительную сессию в заголовке `Authorization: Bearer …`.
Сервер определяет пользователя по сессии; передать чужой ID или токен в query нельзя.
URL с токеном бота остаются только на сервере. Изображение возвращается с `no-store`.

Один загруженный Blob используется в профиле, магазине и примерке рамок. Если фото
отсутствует или не декодируется, отображаются инициалы. При временном сбое загрузка
повторяется; возвращение сети и открытие приложения также обновляют аватар.
Object URL освобождается при смене аккаунта и обновлении изображения.

JPEG, PNG, GIF и WebP передаются без перекодирования. GIF сохраняет все кадры.
Карточки GIF в боте отправляются через `sendAnimation`; PNG — через `sendPhoto`.
Telegram `getUserProfilePhotos` возвращает PhotoSize: для видео-аватара доступно
статичное фото, а само видео не доступно через этот Bot API. Функции отдельной
загрузки GIF-аватара в приложении пока нет.

Успешные загрузки кэшируются на сервере на 5 минут, отсутствие фото — на 1 минуту.
Ошибки Telegram не кэшируются. Лимиты: 2 МиБ на файл, 16 МиБ и 128 записей в кэше.

Проверки: `python -m unittest discover -s tests -v`; браузерные проверки —
`cd tests/webapp && npm install && npx playwright install chromium && npm test`.
Браузерные проверки используют настоящий интерфейс с подменёнными ответами API
и без Telegram SDK: GIF в Android, превью в магазине, инициалы и восстановление сети.
